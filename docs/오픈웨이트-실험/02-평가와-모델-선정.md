# 오픈웨이트 답변 폴백 — 평가와 모델 선정

2026-10-12 · 기준선 `openai/gpt-5.6-luna`(OpenRouter) · GPU는 모두 Modal L4 1대

## 결론

- **선정: Qwen3-8B-AWQ + 프롬프트 v2.** 규칙 준수는 14B와 같고, 응답은 가장 빠르며, L4 한 대로 동시 8~16명을 받는다.
- **Qwen이 규칙을 못 지킨 원인은 모델 크기가 아니라 프롬프트 구조였다.** 14B로 키워도 음악 외 요청 거절은 4/36이었고, 프롬프트 v2에서는 8B·14B 모두 36/36이 됐다. v2는 GPT의 형식 오류도 없앴다.
- **현재 트래픽에서는 오픈웨이트 폴백을 상시 운영하지 않는다.** GPT 답변 1건은 약 $0.0004~0.0005이고, L4를 항상 켜두면 월 약 $580이다. 꺼진 상태에서는 폴백이 실패한다.

## 평가 방법

### 질문 100개, 입력 고정

`scripts/eval/eval.txt`의 질문을 실제 파이프라인(분기·검색, OpenRouter)에 **한 번만** 돌려 답변 단계의 입력(지시문 + 검색된 곡)을 저장했다. 모든 모델에 이 같은 입력을 넣는다. 파이프라인은 실행마다 검색 결과가 달라질 수 있어서, 입력을 고정하지 않으면 차이가 모델 때문인지 입력 때문인지 구분할 수 없다.

| 유형 | 개수 | 보는 것 |
|---|---:|---|
| 일반 추천 (상황·기분·장르·연도) | 30 | 기본 품질, 성능 표본 |
| 음악 외 요청 섞임 (프롬프트 인젝션·유해 요청 포함) | 30 | 첫 문장에서 거절하는가 |
| 곡 수 지정 | 15 | 카드 수와 다를 때 안내하는가 |
| 조합 (곡 수 + 음악 외 / 장르 + 연도) | 10 | |
| 조회, 조회 + 음악 외 | 5 + 5 | 조회 답변, 조회에서의 거절 |
| 외국어 입력 | 5 | 분기가 한국어 질의로 바꾸는가 |

채점의 분모는 질문을 만들 때의 의도가 아니라 **분기가 판정해 답변 모델에 넘긴 값**이다. 답변 모델은 그 값만 보고 행동하기 때문이다. 이 기준으로 "음악 외 요청 포함: 예"가 36건(음악 외 유형 27/30, 조합 5/10, 조회+음악 외 4/5), 요청 곡 수가 카드 수(5)와 다른 경우가 21건(곡 수를 말한 25건 중 5곡을 요청한 4건 제외)이다. 분기가 놓친 음악 외 요청(54·55·57번)은 [03 문서](03-팀-논의-제안.md) 4번에서 다룬다.

**같은 질문을 반복하지 않고 서로 다른 질문을 한 번씩만 보냈다.** vLLM은 prefix caching이 켜져 있어서, 같은 입력을 반복하면 두 번째부터 앞부분 계산을 건너뛰어 TTFT가 실제보다 좋게 나온다. 답변 입력의 대부분은 곡 목록이라 이 효과가 크다.

### 측정과 판정

- 성능: 동시성 1, 워밍업 1건 제외, warm 상태. TTFT·전체 응답 시간의 p50·p95.
- 품질: `backend/chat/answer.py`의 규칙을 지켰는지 **사람이 읽고 판정**했다. 말투와 추천 이유 일치는 보지 않았다. 추천 곡은 OpenRouter와 DB가 정하므로 답변 모델이 바꿀 수 없다.
- 자동 검사는 사람이 먼저 볼 답변에 표시를 다는 용도다. 외국 문자, 문장 수 초과(추천 3·조회 2), 목록, 마크다운, 요청 없는 개수 언급은 위반이 거의 확실하다. 거절 누락과 곡 수 안내 누락은 추정이다.

## 결과 1: 프롬프트 v1 (현재 서비스 프롬프트)

| 모델 | 음악 외 첫 문장 거절 | 곡 수 안내 | 문장 초과 | 마크다운 | 개수 언급 |
|---|---:|---:|---:|---:|---:|
| GPT | 36/36 | 21/21 | 0 | 29 | 23 |
| Qwen3-8B-FP8 | **4/36** | **0/21** | 10 | 0 | 2 |
| Qwen3-14B-AWQ | **4/36** | 약 16/21 (자동 검사) | 11 | 0 | 1 |

8B와 GPT는 100건을 사람이 모두 읽고 판정했고, 14B v1은 자동 검사 수치다.

Qwen은 조회 질문에서 날씨를 지어내거나(93번) 음료를 추천했고(95번), 카드 5곡 중 3곡만 골랐다는 식으로 말했다(73번). GPT는 형식 문제가 대부분이었다. `**` 마크다운을 쓰고, 요청하지 않은 곡 개수를 말하고, 실제 음악 외 요청과 다른 부분을 거절했다(39번: 면접 질문을 물었는데 "레시피나 메뉴 선택"을 거절). 프롬프트의 예시 "(레시피, 메뉴 고르기 등)"를 그대로 가져다 쓴 것이다.

## 프롬프트 v2

v1은 조건부 규칙을 모두 시스템 프롬프트 한 문단에 두고, 입력에는 "음악 외 요청 포함: 예" 같은 값만 준다. 작은 모델은 이 값을 보고 해당 규칙을 스스로 찾아 적용하지 못했다.

v2(`scripts/eval/prompt_v2.py`)는 두 가지를 바꿨다.

1. 시스템 프롬프트를 짧은 규칙 목록으로 바꾸고, 새어 나오던 예시를 뺐다. 마크다운 금지, 언급하는 곡은 최대 2곡, 지어내면 안 되는 것, 내부 용어 금지를 명시했다.
2. **코드가 이번 요청에 해당하는 행동만 골라 입력 끝에 직접 적는다.**

```text
이번 답변에서 반드시 지킬 것:
- 첫 문장은 정확히 "음악 추천과 곡 정보 외의 요청은 도와드릴 수 없어요."로 쓰세요. ...
- 사용자는 3곡을 원했지만 카드는 5곡입니다. 3곡에 맞추긴 어려웠다고 짧게 알리고 5곡을 골랐다고 정확히 말하세요.
- 전체 답변은 3문장 이내로 쓰세요.
```

평가용으로는 저장된 입력에 v2 지시문을 덮어씌워 실행했다. **서비스 코드(`answer.py`)는 바꾸지 않았다.** 입력은 오히려 짧아졌다(Qwen 2,137 → 2,028토큰).

## 결과 2: 프롬프트 v2

| 모델 | 거절 | 문장 초과 | 마크다운 | 개수 언급 | TTFT p50 / p95 | 전체 p50 / p95 | decode p50 |
|---|---:|---:|---:|---:|---:|---:|---:|
| GPT | 36/36 | 0 | **0** | **0** | 1.18 / 2.59초 | 1.88 / 2.91초 | 124 tok/s |
| **Qwen3-8B-AWQ** | **36/36** | 0 | 0 | 1 | 1.15 / 1.25초 | **4.06 / 5.05초** | **27.5 tok/s** |
| Qwen3-8B-FP8 | 36/36 | 1 | 0 | 0 | 1.05 / 1.13초 | 6.47 / 8.18초 | 15.0 tok/s |
| Qwen3-14B-AWQ | 36/36 | 0 | 1 | 0 | 1.70 / 1.84초 | 5.24 / 6.25초 | 25.5 tok/s |

v2 결과는 자동 검사와 표시된 답변의 직접 확인으로 판정했다(100건 전체를 읽지는 않았다). Qwen의 거절 36/36은 지정한 거절 문장이 첫 문장에 그대로 있는지로 셌다.

- GPT는 답이 짧아져(출력 141 → 101토큰) 전체 p95가 3.83 → 2.91초로 줄었다.
- 남은 문제: v2 지시문 표현을 그대로 베낀 3인칭("사용자가 3곡을 요청하셨지만…")이 14B 14건, 8B-AWQ 9건, 8B-FP8 2건이다. **지시를 잘 따르는 모델일수록 지시문의 표현까지 따라 한다.** 이 밖에 데이터에 없는 "대표곡" 설명(14B, 94번), GPT의 페르시아어 단어 섞임 1건(44번)이 있었다. Qwen은 프롬프트를 고칠수록 기존 동작이 깨지기 쉬워 v2로 확정했다.

## 부하 테스트

동시 사용자 N명이 각자 "보내고, 답을 다 받으면 다음 것 보내기"를 반복했다. 입력은 고정 입력을 돌아가며 썼고, 프롬프트는 v2, 단계마다 N × 4건이다(`scripts/eval/load_test.py`).

| 동시 | 8B-AWQ TTFT p95 | 8B-AWQ 처리량 | 8B-FP8 TTFT p95 | 8B-FP8 처리량 | 14B-AWQ TTFT p95 | 14B-AWQ 처리량 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 1.19초 | 20.9 tok/s | 1.46초 | 18.0 | 1.75초 | 19.0 |
| 4 | 1.36초 | 71.9 | 1.33초 | 65.5 | 2.30초 | 56.8 |
| 8 | 1.84초 | 113.6 | 1.83초 | 109.5 | 4.12초 | 84.2 |
| 16 | 4.06초 | **163.1** (1.96 req/s) | 2.35초 | **155.7** (1.87 req/s) | 5.55초 | **99.5** |
| 32 | 7.27초 | 133.6 | 10.54초 | 142.7 | **30.36초** | 68.3 |

- 동시 16까지는 요청을 묶어 처리하는 효과로 GPU 처리량이 동시 1의 약 8배까지 오른다. 32에서는 세 모델 모두 처리량이 떨어진다(포화).
- 14B는 동시 4를 넘으면 첫 글자 지연이 커지고, 32에서 무너졌다(전체 p50 43초).
- 설계 문서(`docs/wiki/week2/07`)의 AI 파트 피크 목표는 6 RPS다. L4 한 대의 최대치는 약 2 RPS(8B-AWQ)이므로, 피크를 오픈웨이트로 감당하려면 L4가 약 3대 필요하다.

## cold start

| 측정 | 시간 |
|---|---|
| 첫 배포 (가중치 다운로드 포함) | 3분 50초 (8B-FP8), 5분 40초 (8B-AWQ) |
| 캐시 후 | 2분 33초 ~ 3분 17초 |
| 구간 (8B-FP8 로그) | 라이브러리 import 17초, 엔진 초기화 26초, **가중치 8.8GB 로드 6초**, 이후 커널·KV cache 준비 |

가중치 로드는 6초뿐이다. 나머지는 import·엔진 초기화·GPU 할당 대기이며, 줄이려면 이 부분을 공략해야 한다(Modal memory snapshot 등). 측정마다 시간이 달라지는 것은 GPU 할당 대기가 매번 다르기 때문이다.

## 비용

| 항목 | 값 |
|---|---|
| GPT 가격 (OpenRouter) | 입력 $0.20, 출력 $1.20 / 100만 토큰 |
| GPT 답변 1건 | 약 $0.00051 (v1), 약 $0.00044 (v2) |
| L4 | $0.80/시간, 항상 켜두면 월 약 $580 |
| 손익분기 | GPU가 켜진 동안 시간당 약 1,560건(v1) ~ 1,800건(v2) 이상 처리해야 오픈웨이트가 저렴 |

Modal은 요청 수가 아니라 켜져 있는 시간으로 과금한다. 요청이 드문드문 오면 매번 부팅(약 3분)과 대기(5분)에 과금되는데, 정작 그 요청은 서버가 꺼져 있어 처리하지 못한다. 현재 규모에서 오픈웨이트는 비용 절감 수단이 아니다.

## 겪은 문제

| 문제 | 원인 | 조치 |
|---|---|---|
| **Qwen이 음악 외 거절 4/36** (8B·14B 동일) | 조건부 규칙이 긴 시스템 프롬프트에 묻혀 있음 | 이번 요청에 해당하는 행동을 입력 끝에 직접 적는 v2 → 36/36 |
| **꺼진 상태에서 폴백 실패** | Modal은 컨테이너가 0대면 요청을 기다리지 않고 0.65초 만에 503으로 거절한다. 그 요청이 부팅을 시작시킨다 | 운영용 폴백은 상시 가동이 필요하므로 실험용으로 유지. 순서를 뒤집는 대안 제안(03 문서) |
| **켜둔 서버가 선점으로 회수됨** | Modal 기본 GPU는 선점형이다. 부팅 완료 1분 30초 뒤 회수된 기록이 있다 | 운영용이라면 `nonpreemptible=True` 필요 |
| **8B-FP8 decode 15 tok/s** | 시작 로그 `Using default W8A8 Block FP8 kernel config... NVIDIA_L4`. L4용 FP8 커널 설정이 없다 | 같은 8B를 AWQ로 바꾸니 27.5 tok/s(1.83배), 품질은 같음 |
| **14B가 동시 32에서 붕괴** | KV cache가 아니라(사용률 약 80%, 66,816토큰) **입력 읽기(prefill) 병목**이다. 로그상 입력 처리 1,000~1,500 tok/s, 생성 16~60 tok/s | 입력 약 2천 토큰의 64%(문자 기준)가 곡 JSON의 이미지·미리듣기·스토어 URL이다. 답변에 쓰이지 않으므로 빼는 것을 제안 |
| **API 키가 로그에 노출** | `vllm serve --api-key ...` 인자를 vLLM이 시작 로그에 평문으로 출력한다 | 키 교체. Secret 환경변수로만 전달하도록 수정 |
| 테스트가 실제 Modal을 호출할 위험 | `main.py`가 `.env`를 읽어 테스트 중에도 폴백이 켜짐 | `tests/conftest.py`에서 폴백 환경변수 제거 |
| `.env.example` 복사 시 폴백이 켜짐 | placeholder `<...>`도 값으로 인식 | `<`로 시작하는 값은 미설정으로 처리 |

## 재현

평가 스크립트는 로컬 전용 폴더(`scripts/eval/`, `.git/info/exclude`)에 있다. 순서는 다음과 같다.

```sh
.venv/bin/python scripts/eval/answer_cases.py                   # 입력 고정 (1회)
.venv/bin/python scripts/eval/answer_run.py openrouter --prompt v2
.venv/bin/python scripts/eval/answer_run.py modal --base-url <URL>/v1 --model Qwen/Qwen3-8B-AWQ --prompt v2
.venv/bin/python scripts/eval/answer_report.py                  # answer_report.md
.venv/bin/python scripts/eval/load_test.py --base-url <URL>/v1 --model Qwen/Qwen3-8B-AWQ --prompt v2 --levels 1 2 4 8 16 32
```
