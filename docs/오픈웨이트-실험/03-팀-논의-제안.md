# 오픈웨이트 답변 폴백 — 팀 논의 제안

2026-10-12 · 근거는 [02 평가와 모델 선정](02-평가와-모델-선정.md)

## 1. 답변 프롬프트 v2를 서비스에 반영할지

**제안: 반영한다.** 오픈웨이트를 쓰지 않더라도 GPT 답변이 좋아진다.

| GPT | v1 (현재) | v2 |
|---|---:|---:|
| 마크다운(`**`) | 29건 | 0건 |
| 요청 없는 곡 개수 언급 | 23건 | 0건 |
| 출력 토큰 / 전체 p95 | 141 / 3.83초 | 101 / 2.91초 |

- 반영 위치는 `backend/chat/answer.py`다. v2는 저장된 입력 텍스트를 다시 읽어 지시문을 만들지만, 서비스에서는 `AnswerHints`에 값이 이미 있으므로 `_request_lines`에서 바로 만들면 된다.
- 바꾼 뒤 같은 질문 100개로 다시 돌려 결과가 같은지 확인한다.
- 알려진 부작용: 곡 수 지시문을 베낀 3인칭 표현("사용자가 3곡을 요청하셨지만")이 생긴다. GPT에서는 0건이었다.
- 서비스 동작이 바뀌므로 폴백 브랜치와 분리해 별도 PR로 진행한다.

## 2. 답변 입력에서 곡 URL을 뺄지

**제안: 뺀다.** 답변 입력 약 2천 토큰 중 **64%(문자 기준)**가 곡 JSON의 `artwork_url`, `preview_url`, `store_url`이다. 답변 모델은 이 값을 쓰지 않는다(곡 카드는 별도 이벤트로 전송).

- 오픈웨이트: 14B가 동시 32에서 무너진 원인이 입력 읽기(prefill) 병목이었다. 입력이 줄면 같은 GPU로 받을 수 있는 동시 사용자가 늘어난다.
- GPT: 입력 토큰 비용이 그대로 줄어든다.
- 확인할 점: 빼기 전후로 답변 품질이 같은지 같은 평가로 비교한다.

## 3. 오픈웨이트 폴백을 운영할지

**제안: 지금은 운영하지 않고 실험용으로 둔다.**

| 운영 방식 | 문제 |
|---|---|
| 지금처럼 0대까지 축소 | 꺼진 상태에서 폴백이 즉시 실패한다(503, 0.65초). 폴백이 정작 필요할 때 동작하지 않는다 |
| 항상 1대 켜두기 | 월 약 $580(L4). 선점 방지(`nonpreemptible`)까지 하면 더 비싸다. GPT 답변 1건이 약 $0.0004인 현재 트래픽에서는 주 경로보다 폴백 비용이 크다 |

**대안: 순서를 뒤집는다.** 오픈웨이트를 주 경로로 두고, 꺼져 있을 때만 OpenRouter로 넘긴다.

```text
요청 → Modal 시도
  ├ 켜져 있음 → 오픈웨이트가 답변
  └ 꺼져 있음 → 0.65초 만에 503 → OpenRouter가 답변, 그 요청이 Modal을 깨움
마지막 요청 후 5분 → Modal 0대 → 과금 멈춤
```

- 사용자가 있을 때만 GPU 비용이 나가고, cold start 공백은 OpenRouter가 메운다. 폴백일 때 단점이던 "즉시 거절"이 여기서는 장점이 된다.
- 비용은 트래픽 모양에 달려 있다. 사용자가 몰리는 시간대가 있으면 유리하고, 요청이 드문드문 하루 종일 오면 매번 부팅·대기에 과금되어 불리하다.
- 대신 GPT보다 응답이 약 2배 느리다(전체 p50 4.1초 vs 1.9초).
- 지금 라우터 구조에서 "오픈웨이트 먼저" 모드를 추가하는 것은 어렵지 않다.

**배포 담당과 확인할 것**

- 서버에서 `*.modal.direct`(HTTPS)로 나가는 통신이 열려 있는지
- `LLM_FALLBACK_*` 값을 시크릿으로 관리하는 방법
- Modal 결제 계정, `max_containers`·`scaledown_window` 상한
- Modal 기본 리전(us-east)과 서울 서버 사이의 네트워크 지연

## 4. 분기 단계: 조회에서 원문이 그대로 넘어가는 문제

답변 모델은 원문 대신 분기가 정리한 `recommend_query`를 받는다. 추천에서는 인젝션이나 음악 외 요청이 여기서 걸러져 답변 모델을 보호한다. 그런데 **조회(lookup)는 원문이 그대로 오는 경우가 있다.**

| # | 원문 | 답변 모델이 받은 요청 |
|---|---|---|
| 91 | 요즘 새로 나온 게임 알려주고 아이유 노래 알려줘 | 아이유의 노래 |
| 93 | 오늘 날씨 알려주고 백예린 노래 추천해줘 | **원문 그대로** |
| 95 | 레드벨벳 노래 보여줘, 무슨 음료수 마시면서 들을까? | **레드벨벳 노래를 들으며 마실 음료 추천** |

v1에서 Qwen이 날씨를 지어내고 음료를 추천한 것이 이 두 건이다. 분기 프롬프트에서 조회일 때의 `recommend_query` 규칙을 정해 두기를 제안한다. 비슷하게 "발매연도도 알아와", "자세한 정보 알려줘"처럼 추천 밖의 요청이 섞였는데도 음악 외 요청이 아니라고 판정된 경우(54, 55, 57번)가 있다.

## 5. v2 VLM 단계에 오픈웨이트를 적용할지

**제안: v2 사진 추천 평가 체계가 갖춰진 뒤에 검토한다.**

v2에는 이미 자체 VLM 폴백 설정(`PHOTO_FALLBACK_URL`·`_MODEL`·`_API_KEY`, OpenAI 호환)이 있다. 서빙(`serving/modal_vllm.py`)은 이미지 입력 설정을 추가하고 VLM 모델로 바꾸면 재사용할 수 있다. 다만 평가는 새로 설계해야 한다.

| | 답변 단계 | VLM 단계 |
|---|---|---|
| 평가 입력 | 텍스트 질문 100개 | 정답 라벨을 붙인 사진 |
| 판정 | 규칙 준수(사람이 훑어봄) | 필드별 정답률·F1, 차단 판정의 정밀도·재현율 |
| 틀렸을 때 | 안내 문장이 어색함 | 검색 쿼리가 바뀌어 **추천 곡 자체가 달라짐** → 추천까지 이어서 평가해야 함 |
| 성능 | 입력 약 2천 토큰 | 이미지 토큰이 더해져 prefill이 더 무거움 |

## 6. 평가 도구를 저장소에 올릴지

지금 평가 스크립트(`answer_cases.py`, `answer_run.py`, `answer_report.py`, `load_test.py`, `prompt_v2.py`, `eval.txt`)는 로컬 전용 폴더에 있어서 팀원이 같은 실험을 다시 돌릴 수 없다. 오픈웨이트 평가 도구만 저장소로 옮기고(결과 파일 제외) 1번·2번 제안의 회귀 평가에 함께 쓰기를 제안한다.
