# 오픈웨이트 답변 폴백 — 구현 현황

2026-10-12 · 브랜치 `feat/open-weight`

**챗봇 답변 단계에서 OpenRouter 호출이 실패하면, Modal GPU에 직접 띄운 오픈웨이트 모델(Qwen3)로 넘긴다. 설정이 없으면 기존과 똑같이 동작한다.**

## 범위와 이유

| 단계 | 오픈웨이트 적용 | 이유 |
|---|---|---|
| 답변 생성 (`stream_answer`) | **적용** (기본값) | 출력이 자유 문장이라 모델을 바꿔도 다음 단계에 영향이 없다. 실측 품질도 쓸 만했다 |
| 분기 (`classify`) | 설정으로만 가능 | 지시문이 약 5천 자로 길다. Qwen3-8B가 "퇴근길 잔잔한 노래"를 정보 부족으로 오판했고 응답에 6~13초가 걸렸다 |
| 추천 이유 (`assign_reasons`) | 설정으로만 가능 | 화면에 표시되지 않고, 파이프라인에서 빠질 예정이다 |
| 임베딩 | 불가 | DB의 곡 벡터와 같은 공간이어야 한다. 바꾸려면 전체를 다시 임베딩하거나 인덱스를 두 벌 유지해야 한다 |

폴백은 OpenRouter 전체 장애가 아니라 **특정 단계·모델만 실패하는 경우**를 가정한다. 전체 장애라면 앞단의 분기와 임베딩이 먼저 실패하므로, 그 대비책은 같은 모델을 다른 공급자로 호출하는 것이다.

## 구조

```text
service.py ── client = with_fallback(OpenAI(OpenRouter))
                 │
                 ├─ classify(client)        ─┐
                 ├─ assign_reasons(client)   ├─ 호출부 코드는 바뀌지 않음 (responses.create 그대로)
                 └─ stream_answer(client)   ─┘
                         │
                FallbackLLM (backend/providers/llm.py)
                 ├─ 1. 요청 모양으로 단계 판별: stream → answer, json_schema 이름 → classify/reason
                 ├─ 2. OpenRouter 시도
                 └─ 3. 실패 + 폴백 대상 단계 → Responses API를 chat completions로 변환해 Modal 호출
                                                   │
                         Modal (serving/modal_vllm.py): L4 GPU + vLLM, OpenAI 호환 API
```

- FastAPI 프로세스에 모델을 올리지 않는다. GPU 추론 서버는 Modal에 따로 두고 HTTPS로 호출한다.
- 스트리밍은 **첫 글자가 나가기 전까지만** 폴백한다. 이미 화면에 찍힌 문장을 다른 모델이 이어 쓸 수 없기 때문이다.

## 서빙: `serving/modal_vllm.py`

| 설정 | 값 | 이유 |
|---|---|---|
| GPU | L4 (24GB, $0.80/시간) | 8B 모델이 들어가는 가장 저렴한 GPU |
| 엔진 | vLLM 0.21.0 | 여러 요청을 묶어 처리(continuous batching). OpenAI 호환 API 제공 |
| `scaledown_window` | 5분 | 요청이 없으면 5분 뒤 0대로 줄어 과금이 멈춘다 |
| `max_containers` | 1 | 실험 단계 비용 상한 |
| `FAST_BOOT` | 1 (`--enforce-eager`) | 0대에서 자주 깨어나는 용도라 부팅 속도를 우선한다 |
| `--max-model-len` | 8192 | 답변 입력은 약 2천 토큰이라 KV cache를 아낀다 |
| 인증 | vLLM API 키 (Modal Secret `llm-serving`) | 환경변수로만 전달한다. 실행 인자로 넘기면 vLLM 시작 로그에 평문으로 찍힌다 |

모델마다 앱을 따로 띄운다(앱 이름 `llm-<모델명>`). 이미지, 가중치 Volume, Secret은 공유한다.

```sh
uvx modal setup                                              # 최초 1회 로그인
uvx modal secret create llm-serving VLLM_API_KEY=<임의 문자열>   # 최초 1회
MODEL_NAME=Qwen/Qwen3-8B-AWQ uvx modal deploy serving/modal_vllm.py
.venv/bin/python serving/smoke_test.py                        # 실제 분기·답변 프롬프트로 확인
```

## 설정 (`.env`)

| 변수 | 용도 |
|---|---|
| `LLM_FALLBACK_BASE_URL` | Modal URL + `/v1`. **비어 있거나 `<...>` 그대로면 폴백 꺼짐** |
| `LLM_FALLBACK_API_KEY`·`_MODEL` | Modal Secret의 키, vLLM 모델명 |
| `LLM_FALLBACK_EXTRA_BODY` | Qwen3 생각 모드 끄기: `{"chat_template_kwargs": {"enable_thinking": false}}` |
| `LLM_FALLBACK_SLOTS` | 폴백할 단계. 기본 `answer` |
| `LLM_FALLBACK_TIMEOUT` | 폴백 요청 타임아웃. 기본 60초 |

실험 전용 변수는 `.env`에 넣지 않고 명령 앞에 붙여 쓴다.

| 변수 | 용도 |
|---|---|
| `LLM_FAULT_SLOTS=answer` | 그 단계의 OpenRouter 호출을 일부러 실패시킨다 (부분 장애 재현) |
| `LLM_ROUTE=fallback` | 폴백 대상 단계를 처음부터 오픈웨이트로 보낸다 (오프라인 비교) |
| `LLM_METRICS_PATH=metrics.jsonl` | 호출마다 단계·경로·폴백 사유·지연·TTFT·토큰을 기록한다 |

```sh
# 답변 단계만 장애를 내고 실제 파이프라인으로 확인
LLM_FAULT_SLOTS=answer LLM_METRICS_PATH=metrics.jsonl \
  .venv/bin/python scripts/eval/chat_eval.py --runs 1 "퇴근길에 듣기 좋은 잔잔한 노래 추천해줘"
```

## 테스트

`tests/providers/test_llm.py` (10개). 가짜 client로 다음을 보장한다.

- 설정이 없거나 `.env.example`의 placeholder가 남아 있으면 감싸지 않는다
- 분기 실패 시 같은 지시·입력·json_schema를 chat completions 모양으로 바꿔 폴백한다
- 폴백 대상이 아닌 단계는 기존처럼 오류를 올린다
- 스트리밍은 첫 글자 전 실패만 폴백하고, 글자가 나간 뒤 실패는 그대로 실패 처리한다
- 장애 주입은 지정한 단계만 실패시키고, `LLM_ROUTE=fallback`은 폴백 대상 단계에만 적용된다
- 호출 기록에 경로와 폴백 사유가 남는다

`tests/conftest.py`는 테스트 중 폴백 환경변수를 항상 지운다. `main.py`가 `.env`를 읽기 때문에, 지우지 않으면 테스트가 실제 Modal을 호출할 수 있다.

## 확인된 동작

장애 주입으로 실제 파이프라인을 돌린 결과, 분기와 추천 이유는 OpenRouter로 처리되고 답변만 Qwen으로 넘어가 정상 완료됐다(곡 카드 5개, 첫 글자 4.4초, 부팅 직후 첫 요청 기준).

같은 실험에서 **Modal이 꺼져 있으면 폴백도 실패**하는 것을 확인했다. 원인과 판단은 [02 문서](02-평가와-모델-선정.md)의 "겪은 문제"를 참고한다.
