# 음악 추천 AI 설계 Wiki

이 Wiki는 사용자가 텍스트·음성·사진으로 전달한 순간과 분위기를 바탕으로 실제 재생 가능한 음악을 추천하는 AI 서비스의 설계 근거를 정리합니다.

현재 저장소는 FastAPI 기반 채팅 프로토타입 단계입니다. `/chat` 요청과 텍스트·STT 입력 흐름은 확인할 수 있지만, 실제 추천 모델과 음원 카탈로그 연동은 아직 확정되지 않았습니다. 따라서 문서에서는 구현된 사실, 설계 결정, 검증 예정 사항을 구분합니다.

## AI가 해결하는 사용자 문제

- 사용자가 현재 상황과 감정을 길게 설명하지 않아도 추천에 필요한 맥락을 수집합니다.
- 텍스트와 음성 입력을 같은 추천 흐름으로 처리하고, 사진 입력은 검증 후 단계적으로 추가합니다.
- 추천 이유와 실제 곡 정보를 함께 제공해 사용자가 결과를 이해하고 재생할 수 있게 합니다.
- 모델이 실패하거나 결과를 만들지 못해도 사용자가 다시 입력하거나 조건을 수정할 수 있게 합니다.

## 설계 원칙

- 외부 API는 특정 LLM 제공업체가 아니라 음악 추천이라는 서비스 행위를 표현합니다.
- LLM이 만든 곡 정보를 그대로 신뢰하지 않고 음원 카탈로그에서 실제 곡을 확인합니다.
- 평균 응답 시간만 보지 않고 지연 분포, 실패율, 비용, 추천 품질을 함께 측정합니다.
- 모델 호출, 추천 정책, 카탈로그 조회를 분리해 모델이나 공급자를 바꿀 때의 영향 범위를 줄입니다.
- 아직 측정하지 않은 수치는 성과처럼 표현하지 않고 가설 또는 목표 후보로 표시합니다.
- 기술 선택은 “우리 서비스에 왜 필요한가”와 “어떻게 검증할 것인가”를 함께 설명합니다.

## 문서 갱신 기준

- API 계약이 바뀌면 모델 API 설계 문서와 계약 테스트를 함께 갱신합니다.
- 모델·프롬프트·캐시 정책이 바뀌면 동일 평가 세트의 전후 결과를 남깁니다.
- 모듈 경계나 배포 단위가 바뀌면 아키텍처 문서와 다이어그램을 함께 갱신합니다.
- 결정되지 않은 항목은 숨기지 않고 열린 질문과 결정 조건으로 기록합니다.
