# 사진 추천 실험 — 구현 현황

2026-10-08 · 브랜치 `experiment/v2-photo-recommendation` · **개인 실험 구현이며 팀 확정 계약이 아님.**

**사진 1장 → 검증·정규화 → VLM 판정·장면 분석 → 기존 Gemini 임베딩·PostgreSQL 검색 → 기존 채팅(`thread_id`)에 추천.**

## 실행

```sh
uv sync --locked
uv run uvicorn backend.main:app --host 127.0.0.1 --port 8012
```

- 테스트 UI: `http://127.0.0.1:8012/app/` → 사진 버튼. 협업 테스트용이며 실제 FE가 아님.
- 별도 활성화 스위치·실행 모드 없이 V1 채팅처럼 항상 켜짐. 인증·요청 제한은 BE 담당.
- 실제 모델·DB를 호출해 비용이 발생함. Python 코드를 바꾸면 서버를 재시작해야 하고, 재시작하면 메모리 대화가 초기화됨.

| `.env` | 용도 |
| --- | --- |
| `PHOTO_VLM_MODEL` | OpenRouter VLM(이미지 입력·JSON Schema 지원). 기본값 없음. 지정하지 않으면 호출하지 않음 |
| `PHOTO_FALLBACK_URL`·`_MODEL`·`_API_KEY` | 자체 VLM(OpenAI 호환). 3개가 모두 있을 때만 폴백 |
| 기존 LLM·임베딩·DB 설정 | 분석 키, 임베딩, 검색, 곡별 이유 |

## 처리 흐름

| 단계 | 내용 |
| --- | --- |
| 입력 검증 | 5 MiB·6천만 픽셀 이하. MIME 값 대신 실제 바이트와 디코딩으로 JPEG 여부 판단 |
| 정규화 | 원본 픽셀 검사 → 축소 디코딩(`draft`) → EXIF 회전 → 긴 변 1024px → 메타데이터 제거 |
| VLM | 적합 판정, 장면 필드, 검색 문장(`music_query`), 설명(해요체로 지시). 사진 속 글자는 보조 맥락으로만 사용 |
| 검색 | `music_query`로 기존 임베딩·검색·곡별 이유를 재사용. 의도 분류 단계는 생략 |
| 응답 | VLM 설명을 판정 직후 먼저 전송. 곡이 없으면 안내 문장을 덧붙임. 최종 답변 LLM 호출 없음 |

## SSE 이벤트

- 적합: `status` → `verdict` → `scene` → `text` → `status` → `tracks` → `done`. 설명(`text`)은 판정 직후, 곡 카드는 검색 후
- 부적합: `status` → `verdict` → `scene` → `rejected` → `done`
- 공급자 차단: `verdict(provider_blocked)` → `rejected` → `done`. 중립 문구를 쓰며, 서비스가 부적절하다고 판정한 것이 아님
- 실패: `error {detail, reason}`. `reason`은 `MODEL_RESPONSE_INVALID` / `MODEL_UNAVAILABLE` / `PHOTO_TIMEOUT` / DB·설정 사유
- `status`·`scene`·`rejected`는 실험 인스펙터용이며 정식 계약이 아님

## 요청 제어

| 항목 | 정책 |
| --- | --- |
| 동시 처리 | 프로세스당 2건, 같은 채팅은 1건. 초과하면 대기 없이 409 `PHOTO_BUSY` |
| 중복 | 같은 `thread_id`+`request_id`는 409 `DUPLICATE_REQUEST` (최근 256건·10분 보관) |
| 같은 ID 재시도 | 분석 결과를 받기 전에 실패한 경우만 허용. 판정·차단·검색 시작 이후에는 새 ID 필요 |
| 제한시간 | 전체 45초, 주 VLM 10초, 폴백 20초. 시간 초과 후에도 남은 작업이 끝나면 처리 슬롯 반환 |
| 폴백 | 429·5xx·통신 오류에서만 1회. 400·401·형식 오류·차단은 폴백하지 않음 |
| 보관 | 사진 파일을 저장하지 않음. 정규화 이미지는 요청 동안 메모리에만 있음 |

## 검증

- `uv run pytest -q`: 133개 통과(사진 40개). 외부 호출 없음.
- 실서버에서 확인한 것:
  - 입력 오류 6종 차단
  - 빈 화면·1픽셀 사진 거절(약 2초)
  - 사진 속 글자로 넣은 지시를 따르지 않음
  - 다른 채팅 2건 동시 처리
  - MIME이 잘못 붙은 정상 JPEG 통과

## 알려진 한계

1. 폴백은 VLM 단계만 대체함. 카탈로그 벡터가 Gemini 공간이라 임베딩·곡별 이유는 계속 OpenRouter에 의존함.
2. 처리 제한과 중복 기록은 프로세스 단위임. 다중 워커, 같은 채팅의 사진·텍스트 동시 요청은 보장하지 않음.
3. 해요체는 프롬프트 지시뿐임. 실측 2건 중 1건이 지키지 않음.
4. 응답까지 약 7초(동시 2건이면 약 10초). 곡별 이유 LLM 호출이 포함된 시간이며, 이 호출의 제거는 별도 이슈.
5. 미적용: OpenRouter `data_collection: "deny"`, `scene` 원문 노출 축소, 글자만 있는 사진의 허용 여부.
