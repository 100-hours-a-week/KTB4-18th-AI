# 한국어 발라드·K-pop 고정 테스트 데이터

기준: [DB 스키마](../db-schema.md). 실제 곡 수집 결과가 아닌 **가상의 곡·아티스트·메타데이터·태그·벡터**다. 개인정보, 실제 iTunes ID, 음원 파일을 포함하지 않는다. 운영 DB에 적재하지 않는다.

- `catalog.json`: `tracks` 14행과 `corpus_stats` 1행. 행 내부의 키는 문서의 컬럼과 일치한다. 날짜·시각은 JSON 문자열이며 벡터는 숫자 배열이다.
- `cases.json`: 검색 벡터와 기대 순위, 조회·라우팅 시나리오. 테스트 제어 정보는 DB 행 바깥에 둔다.
- `backend/tests/test_catalog_fixture.py`: 형식·검색 순위·조회·카드 매핑을 외부 호출 없이 검사한다. 실제 워크플로우나 PostgreSQL 통합 테스트는 아니다.

## 데이터 구성

| ID | 가상 곡 | 확인 목적 |
|---|---|---|
| -1, -2 | 서하 — 비가 머문 밤 | 앨범만 다른 동일 곡의 중복 제거 |
| -3 | 서하 — 너에게 남긴 계절 | 특정 아티스트 요청 시 여러 곡 허용 |
| -4 | 윤별 — 창가의 온도 | 잔잔한 발라드 후보 |
| -5, -7 | 루미나 — 네온 스텝 / 별빛 달리기 | 같은 아티스트의 K-pop 후보 |
| -6 | 블루아워 — 여름 신호 | 다른 아티스트의 K-pop 후보 |
| -8 | 민솔 — 봄의 대답 | 벡터 NULL, 처리 대기. 상세 조회 가능 |
| -9 | 한결 — 늦은 안부 | 벡터 NULL, 실패 3회. 배치 자동 재시도 제외 |
| -10 | 리온 — 어제의 우리 | 벡터는 있지만 구버전. 현재 추천 제외 |
| -11 | 도하 — 숨 고르는 밤 | 태그·앨범·장르·스토어·아트·길이 누락 |
| -12, -13 | 하린 / 새봄 — 안녕 | 제목만으로 조회하면 대상 확인 필요 |
| -14 | 서하 & 윤별 — 비가 머문 밤 | 협업 표기 차이. 단순 artist/title 중복 제거의 한계 |

음수 ID는 실제 iTunes ID와 구분하기 위한 테스트 전용 BIGINT다. URL은 예약 도메인 `example.invalid`를 사용하여 실수로 실제 음원을 요청하지 않게 한다. 형식 검사에는 쓸 수 있지만 재생·이미지 표시 성공 테스트에는 사용할 수 없다. 실제 노래 제목이나 분위기에 대한 주장을 담지 않는다.

## 벡터와 기대값

512차원 중 앞의 세 좌표만 사용한 단위 벡터다. 1번 축은 발라드 사례, 2번 축은 신나는 K-pop 사례를 구성하기 위한 임의의 수학적 축이며 실제 CLAP 의미 공간이 아니다. `corpus_stats.clap_mean`은 0벡터로 두었다. **평균 벡터의 0은 유효하며 검색 벡터의 0과 구분한다.**

검색 조건은 `emb_clap != null`과 활성 `model_version` 일치다. 코사인 유사도 내림차순, 동점이면 숫자 `track_id` 오름차순으로 고정한다. `limit`은 최종 카드 수가 아닌 검색 후보 수다. `expected_after_exact_dedup_track_ids`는 이 후보에서 공백 정리·대소문자 정규화한 `(artist, title)` 중복만 제거한 결과다. 아티스트 다양성 재정렬 이전 값이며 -14는 별도 협업곡으로 남는다.

0평균이므로 실제 중심화 수식을 검증할 수 없다. 테스트가 통과해도 추천 품질·모델 성능·중심화·음원 재생·DB 쿼리 성능을 검증한 것이 아니다. `route_cases`는 향후 워크플로우의 수용 사례이며 현재 LLM 분류 통과 결과가 아니다.

실행: 저장소 루트에서 `uv run pytest backend/tests/test_catalog_fixture.py -q`.

실제 그래프 테스트에서는 이 JSON을 테스트에서만 로딩해 검색 함수를 주입한다. 운영 `search_tracks()`의 DB 장애를 이 데이터로 자동 대체하지 않는다. SQL 적재가 필요하면 DB 담당자의 실제 DDL·기본값·제약을 받은 뒤 별도 테스트 DB에서 수행한다.
