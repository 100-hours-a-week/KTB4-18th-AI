# 평가 기준 — initial-metrics-20261031-v2

## 사람이 보는 지표

`compare_runs.py`가 아래 지표만 출력한다. 나머지 지표는 원본 파일에 그대로 저장한다.

| 지표 | 보는 내용 | 읽는 법 |
|---|---|---|
| 기능 요구 충족 | 경로·곡 수·장르·연도·마크다운·안내 장르 약속을 모두 지켰는지 | 건수와 바뀐 사례로 본다 |
| 안내 근거 충실도 | 곡 카드가 있는 턴의 안내문이 근거 없는 말을 했는지 | 말을 줄여도 오르므로 숨긴 안내 적절성과 답변 길이를 함께 본다 |
| 장면 해석 점수 | 사진을 맞게 이해했는지 (0~3) | 같은 답변 재채점에서 12턴 중 2턴이 달라졌다. 0.17 안팎의 차이는 개선으로 말하지 않는다 |
| 곡 반복 | 가장 많이 나온 곡이 곡 카드가 있는 사례의 몇 %에 나오는지 | 음악 적합성과 함께 판단한다 |
| 첫 안내 대기 | 첫 안내가 나올 때까지의 서버 내부 시간 중앙값과 p90 | 기능별로 두 실행에 모두 값이 있는 같은 턴만 비교한다. 브라우저·네트워크 시간은 포함하지 않는다 |
| 추천 카드 대기 | 카드가 나올 때까지의 서버 내부 시간 중앙값과 p90 | 첫 안내 대기와 같다 |
| 요청당 비용 | 기능별 서비스 비용 합계 ÷ 요청 수 | 누락이 있으면 값을 내지 않고 누락 건수를 보여 준다 |
| 서비스 비용 합계 | 평가 1회에 쓴 서비스 모델 비용 합계 | 누락은 0달러가 아니라 경고로 표시한다 |

- **자동 경고:** 요청·대화 완료율, 전사 성공률, 구조화 응답 성공률, LLM 채점 완료율, 장애 처리 통과율, 문자 오류율 상승.
- **실패 때만 열람:** 의도 분류, 조건 추출, 명시 조건, 곡 수, 이전 곡 제외, 이미지 입력 판정, 마크다운, 안내 장르 일치.
- **저장만 함:** 전체 처리 시간, 평가 비용, 정상 거절 시간, 검색 문장 일관성, 안내 적절성, 응답 요구 준수율.
- **음악 적합성:** 자동 평가로 잴 수 없다. 검색을 바꿀 때만 사람이 듣고 평가한다.
- **고속 모드(Jev):** 평가하지 않는다.

## 2026-10-31 규칙 변경

| 변경 | 내용 | 비교할 때 |
|---|---|---|
| 안내 장르 일치 | 안내문이 클래식·재즈·힙합·뉴에이지·메탈·컨트리를 말했는데 카드의 40% 미만이면 실패 | `compare_runs.py`가 두 결과를 같은 규칙으로 다시 계산한다 |
| 마크다운 검사 | 모든 턴에 적용 | 위와 같다 |
| 고정 문구 채점 제외 | 곡 카드가 없는 턴은 LLM 채점을 하지 않음 | 이 규칙 이후 결과만 서로 비교한다 |
| 한국어 정책 전달 | 영어 답변 요청에 한국어로 답한 것을 위반으로 보지 않음 | 채점 규칙 `20261031-reviewed-v3` 이후 결과만 서로 비교한다 |

`compare_runs.py`는 완료 현황과 지표별 분모도 함께 출력한다. 분모는 그 검사를 실제로 받은 수이며 전체 사례 수가 아니다.

10-27 의미 점수와 새 채점 규칙의 의미 점수는 직접 비교하지 않는다. 조건 미충족 안내 검사는 서비스에 그런 안내가 없어 아직 만들지 않았다.

## 전체 지표 정의

| 대상 | LangSmith 지표 | 판정·계산 |
|---|---|---|
| 공통 | 요청 완료율 / 대화 완료율 / 전사 성공률 | 오류 없이 필수 완료 조건을 만족한 사례 ÷ 전체 사례 |
| 공통 | 첫 안내 대기 시간(s) / 추천 카드 대기 시간(s) / 전체 처리 시간(s) | 서버 내부 라우터 호출 시작부터 해당 이벤트까지. 브라우저·네트워크 포함 TTFT가 아님. p50/p90과 표본 수 병기 |
| 공통 | 서비스 비용(USD) / 평가 비용(USD) | 실제 공급자 사용량의 비용. 누락은 0달러가 아님. 누락률을 따로 보고 |
| 텍스트 | 의도 분류 정확도 | 고정 기대 경로와 실제 경로 일치. 실패를 정답으로 세지 않음 |
| 텍스트 | 조건 추출 정확도 | 연도·장르·곡 수 등 명시 기대 필드의 일치율 |
| 텍스트 | 명시 조건 충족률 / 요청 곡 수 준수율 | 반환곡의 DB 장르·연도 및 반환 개수로 코드 판정. 음악적 취향 적합률을 뜻하지 않음 |
| 텍스트 | 응답 요구 준수율 | 입력·이력·기준 조건을 보고 독립 LLM이 0/1 판정 |
| 텍스트 | 안내 근거 충실도 / 안내 적절성 점수 | 근거 없는 곡 특성 단정 0/1, 유용성·명확성 0~3. 이유와 원출력 보존 |
| 이미지 | 이미지 입력 판정 정확도 | usable 정답과 실제값 일치. 차단·타임아웃·JSON 실패는 실패로 포함 |
| 이미지 | 구조화 응답 성공률 | 정상 스키마 장면 출력 ÷ 전체 사진 |
| 이미지 | 장면 해석 점수 / 검색 문장·설명 일관성 점수 | 원본 사진을 제공한 LLM이 각각 0~3 판정. 모델 scene을 정답으로 삼지 않음 |
| 이미지 | 정상 거절 처리 시간(s) | 판독 불가 입력을 올바르게 거절한 경우만 집계 |
| 멀티턴 | 대화 완료율 / 이전 곡 제외율 / 기능 요구 충족률 | 3턴 전체 완료, 기존 카드와 ID 비교, 턴별 경로·조건 확인. 단일 요청 결과와 분리 |
| 음성 | 문자 오류율(CER) | NFKC·소문자·공백/문장부호 제거 후 편집거리 ÷ 정답 글자 수. 원문과 전사도 보존 |
| 장애 | 장애 처리 통과율 | dev checkout의 지정 pytest 20검사. 공급자는 모의 처리하며 실제 공급자 가용성 지표가 아님 |

코드 채점의 세부 필드 평균은 먼저 사례 안에서 계산한 후 사례 평균으로 요약한다.
LLM 채점 실패는 품질 0점으로 바꾸지 않고 `LLM 채점 완료율`과 오류로 표시한다.
곡을 청취하지 않으므로 음악적 적합률은 이번 자동 평가의 확정 지표에서 제외한다.
채점 모델은 Claude Sonnet 5.5이고 사진 판정 모델은 Gemini 계열이다.

## 재실행

`baseline_suite.py --service-root <깨끗한 checkout> --output <새 결과 폴더> --name <고유 실험명> --execute`

서비스 Git SHA, 평가 코드/프롬프트 해시, 데이터셋 버전, 모델, 동시성, DB 전후 지문을 남긴다.
동일 데이터·평가기·모델·검색 설정·DB에서 비교해야 한다. DB 지문이 바뀌면 직접적인 코드 효과 비교로 단정하지 않는다.
카드 대기는 성공한 추천만 집계하며, 빠른 거절 응답과 섞지 않는다. 비용은 루트 합계와 하위 호출을 중복 합산하지 않는다.
